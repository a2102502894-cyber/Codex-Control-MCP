# 异常回执与维护并发修复（2026-09-24）

本修复基于 `0bf57cd`，不改变工具权限声明、鉴权、官方运行环境或上游安全检查。

## 修复范围

### 操作结果与记录失败分开

执行前的 HTTP 和桥接接收日志仍为强制要求。若无法写入，不下发新操作。

操作已执行后，写入 `tool_finish`、`http_tool_receipt`、HTTP 结束日志，或完成幂等记录时发生二次故障，不再抹去已经取得的操作结果。记录异常通过明确的诊断字段报告，不作为重复执行的理由。若原始连接也有异常，保留原始连接异常，不被后续日志异常覆盖。

幂等结束写入失败时，原始 `started` 预留记录仍在；同一个键不会再次执行。`ok` 表示操作本身的结果，不代表日志和持久化都成功，调用方应同时检查 `diagnostics.audit_recording` 和 `diagnostics.idempotency_persistence`。

### 审计故障可见性

真实 Audit 对象保留有界的进程内写入失败计数、最后一次失败时间及异常类型。健康回执新增 `audit_observation`。写入恢复后仍保留本进程的失败计数，不记录异常正文、路径、命令、令牌或业务内容。

这些内存计数不跨进程重启保存，不能代替独立的日志存储监控。HTTP 回执中的 `transport_observation` 只描述创建回执时的状态，不提前保证后续网络交付成功。

`response_complete` 的含义明确为服务器 ASGI 发送函数已经返回，不等同于远端客户端已收到或显示结果。

### 维护请求并发与有效期

原生维护入口增加跨进程互斥锁，锁内再次核对控制器状态。已有待处理 JSON 请求时，停止叠加新的重启请求，不删除其他请求，也不启动补偿性重试。

控制器启动失败时，使用原子移动撤回本次尚未被领取的请求，而不是先判断文件存在再删除；已经被领取的请求保留“状态未知”的结论。

维护控制器对请求采用 16 KiB 有界读取，拒绝不支持的结构版本及未来超过 30 秒的时间戳，继续拒绝超过 5 分钟的请求。维护报告仅保留已知字段。

## 回归与证据

`tests/test_failure_edges_20260924.py` 前 12 个用例在旧实现上失败，覆盖回执丢失、错误被替换、并发重复提交以及异常维护请求被接受。另增加 2 项真实文件写入故障与恢复可见性测试。

本机验收证据保存在被 Git 忽略的 `evidence/` 目录。测试专用工作目录与回滚备份不上传 GitHub。最终以全套测试 XML、测试源码哈希清单、官方运行环境真实调用回执和正式服务加载回执为准。

旧测试中“其他文件不被删除”的夹具改用非请求文件 `.keep`。JSON 待处理请求由新的独立用例验证为应阻止叠加提交，原有数据保留断言没有删除。
