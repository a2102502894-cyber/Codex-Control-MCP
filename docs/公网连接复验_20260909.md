# 2026-09-09 公网连接补充修复与 Browser 状态

运行中的应用仍是 Codex-Control-MCP 0.1.9。本次改动范围为公网验收客户端、连接故障夹具和文档；未修改生产 EXE、官方 Runtime、Clash、系统代理、DNS、路由或防火墙。0.1.9 冻结交付 ZIP 保持原样。

用户将本轮目标收敛为 Browser 与公网连接。Remote 和加密流量用途核验移出本轮范围，历史未通过和未知项仍然保留。

## 公网失败定位

使用原验收客户端连续执行三轮，结果为 PASS、PASS、FAIL。前两轮各完成 17 项断言、最终健康检查及 MCP 会话关闭。第三轮首个请求尚未进入 MCP 业务处理便失败。

该次失败的事件顺序为：连接现有本机代理成功 → HTTP CONNECT 成功 → `proxy.start_tls` 约 5 秒后以 `EndOfStream` 结束 → HTTPX 返回 `ConnectError`。这定位到测试客户端经现有代理建立公网 TLS 的阶段，不能据此断言 Clash 程序本身或某个上游节点存在缺陷。

本机 HTTPX 0.28.1 / httpcore 1.0.9 的实现显示，普通连接重试循环覆盖 TCP 和直接 TLS，而代理 CONNECT 后的 `proxy.start_tls` 在另一段代码中。原先配置的 `retries=2` 因而没有覆盖本次失败的握手阶段。

## 已实施的修复

`scripts/public_transport.py` 包装 HTTPX 官方传输层，为明确发生在目标 HTTP 请求发送前的 TCP/TLS 建连失败提供最多 3 次重试，并恢复有界 HTTP 连接复用，减少反复握手。

重试需要同时满足：异常为 ConnectError 或 ConnectTimeout；跟踪事件明确属于建连阶段；目标 HTTP 请求头尚未开始发送；异常不是证书校验失败。未知阶段、请求发出后的错误、响应读取错误、HTTP 503、证书错误均不会触发重放。TLS 校验保持启用。

`tests/verify_release_https.py` 已接入该传输层，每次默认创建独立的 `evidence/public-*` 目录，保存业务断言和不含凭据的连接事件，不覆盖旧版本验收记录。

修复作用于本项目的公网验收客户端。它不会改变 ChatGPT 自身的 HTTP 客户端，也不是对系统网络或 Clash 的修改；生产 MCP 服务本次无需重启。

## 实测结果

| 测试 | 结果 |
| --- | --- |
| 原客户端完整批验 | 前两轮各通过 17 项，第三轮在 TLS 握手失败，保留失败记录 |
| 修正客户端完整批验 | 连续 3 轮通过，每轮 17 项及最终健康检查、会话关闭 |
| 真实间歇失败恢复 | 修正后的第 2 轮遇到一次握手断开，恢复连接后完成整轮 |
| TLS 握手故障夹具 | 第一次握手断开，第二次成功；目标 POST 只到达 1 次 |
| 已收到 POST 后丢失响应 | 返回协议错误，不重发；目标 POST 只到达 1 次 |
| HTTP 503 | 保留 503，不重试 |
| 无效证书 | 保留校验错误，不重试，不关闭 TLS 校验 |
| 连续建连失败 | 达到 3 次重试上限后退出，目标 POST 到达 0 次 |

完整批验包括缺失/错误鉴权、OAuth 发现与挑战、关闭配对窗口时拒绝注册、Origin 检查、未发布路由、服务身份和 29 个工具、官方 Shell、中文文件往返及删除、流式会话输入输出和健康状态。

## 复跑

从项目目录执行，须使用本机所有者账号，以便读取本项目 DPAPI 凭据；凭据只在内存中使用。

```powershell
$env:PYTHONPATH = Join-Path $PWD 'src'
& '.\.venv\Scripts\python.exe' scripts/verify_public_transport.py
& '.\.venv\Scripts\python.exe' tests/verify_release_https.py
```

每次运行生成新的证据目录。正在进行交互配对时，公网批验会拒绝启动，避免消耗真实配对窗口。

## Browser 当前状态

保持官方插件原始 CODEX_HOME、使用本项目独立 App Server 创建的真实非模型会话和回合标识后，官方浏览器列表仍为空，创建内置浏览器返回 `Browser is not available: iab`。专属探针结束后所属进程已退出；官方清单和 Codex Desktop 全局配置哈希未变，未启动 Remote 或模型回合。

官方诊断另发现本机 Edge 缺少 Browser 扩展，且本机通信宿主清单及其注册项不存在。这是独立的安装依赖问题；不能声称安装扩展后就一定解决独立 MCP 的宿主可用性。

官方文档说明 Browser 不在 Codex CLI / IDE 扩展中提供。内置 Browser 属于桌面/网页宿主，不能把当前助手可操作的浏览器直接算作本项目已通过。参考：[官方 Browser 文档](https://learn.chatgpt.com/docs/browser)。

现有需求规格 v1.2 第 5 节要求只发布实测通过的官方 Browser 路径。已向用户提出路线选择：允许为 8 个 Browser 工具增加独立 Playwright/Chromium 后端，或继续坚持官方 Browser 并处理官方安装依赖。收到选择前 Browser 仍保持禁用，未标记为 PASS。

连接重试接口的官方说明：[HTTPX Transports](https://www.python-httpx.org/advanced/transports/)。代理 TLS 重试缺口的具体判断以本机 0.28.1 / 1.0.9 实现与上述真实故障记录为依据。
