# Codex-Control-MCP 正式需求规格 v1.2

日期：2026-09-08。用户已批准开发，并明确授权完整权限、无沙箱。本文件整合原37节与v1.1修订，覆盖与最新授权冲突的旧沙箱条款。实现状态以验收报告为准，需求中的目标不是已实现声明。

## 1. 项目边界

外部GPT是唯一理解、规划、推理、判断与决策主体。本项目独立安装、动态依赖官方Codex，负责确定性的MCP协议转换、能力发现、参数校验、会话、执行调度、版本兼容和结果回传。不Fork、不修改或复制官方Runtime，不内置LLM，不调用Codex agent完成普通执行，不模拟ChatGPT API，不要求推理API Key。

执行链：外部客户端 → 标准MCP → 本项目 → 官方App Server或经过验证的官方插件 → 原Windows项目目录。不得复制业务项目；不得重建Computer Use、Shell或Git Runtime；官方后端失败后不得偷偷切换到桥接程序自己的执行器冒充成功。配置、协议、输出缓存及进程生命周期管理属于桥接职责，不属于复制Runtime。

2026-09-09 用户批准的 Browser 专项变更：独立官方 Browser 宿主不可用，用户明确同意 Playwright/Chromium 路线并指定已安装的 Tabbit。因此 Browser 可使用本项目独立 Playwright 驱动，必须如实标注实际后端，通过真实 Tabbit 与打包 EXE、HTTP、公网全动作验收后启用；不可称为官方 Codex Browser。其他执行层要求不变。使用专属浏览器配置和管道，禁止复制日常浏览器登录凭据。Remote 与加密请求具体用途核验由用户移出当前验收范围。

AgentDock可用于开发和维护，不是产品运行依赖；不得修改其配置、抢占其端口或循环互调。测试不得触碰H8量化或AI短剧内容。

## 2. 用户授权：完整权限、无沙箱

默认权限模式：`trusted_owner_full_access`。官方命令显式传入 `sandboxPolicy.type=dangerFullAccess`；桥接拥有的官方进程采用 `sandbox_mode="danger-full-access"` 和 `approval_policy="never"`。不创建VM、Docker或Windows Sandbox；不强制虚构工作区白名单；对已授权的普通执行不再增加一轮模型判断或人工审批。

继承启动进程的Windows令牌。管理员启动后必须实测子进程保留管理员权限；普通启动不得谎报管理员。提权只走正常UAC；不绕过UAC，不取得SYSTEM或TrustedInstaller，不关闭Defender、防火墙、Windows审计或系统防护，不改变Codex Desktop全局配置。

`risk_level=read|write|dangerous`由桥接确定并回传，是审计分类，不是另一层沙箱。任意Shell按dangerous标记，不能靠关键词扫描假称只读。RPC白名单用于保证无模型执行和已知协议语义，不限制用户显式Shell指令的文件访问范围。

完整权限不等于允许未知网络客户端访问电脑。HTTP入口仍必须鉴权、Host/Origin校验、请求限额和速率控制；默认loopback，公网须TLS。不能裸露官方App Server。权限提示或宿主授权不可伪造、复制、绕过。

## 3. 动态官方依赖

按显式配置、系统注册安装信息、官方AppData运行时、Windows App Package和PATH候选进行有界发现。允许辅助检查实际运行实例，不把特定哈希目录写进业务代码，不递归扫描整盘。

选中真实二进制后读取版本、帮助和Schema。记录路径、来源、CLI/桌面版本、安装指纹与Schema Hash。目录存在只证明安装线索，不证明接口能调用。

只有官方提供经过验证的多客户端入口时才复用Desktop App Server，不抢占stdio。否则桥接启动自己独占的官方App Server和控制连接，不占用Desktop thread writer。配置/缓存可用桥接专属Codex Home，不复制auth.json或登录令牌。只清理自己拥有的进程。

## 4. 两段协议和客户端

对外标准MCP，对内官方App Server JSON-RPC，独立处理初始化、请求ID、通知和错误。首发实现stdio和带鉴权的Streamable HTTP，使用锁定版本的受维护官方MCP SDK。

本机stdio或HTTP测试通过不能代替ChatGPT网页验收。网页必须实际调用可达的HTTPS MCP并取得本机返回。官方Secure MCP Tunnel属于可选方案，其API凭据及工作区要求必须明确，不作为零推理Key目标的默认前提。Remote Control离线不应影响本地MCP。

对外工具名和Schema保持小而稳定。未知官方RPC不自动发布；新增工具可能需要客户端刷新，不能假定当前ChatGPT会话自动更新。

## 5. 核心工具

### Shell

`exec_command(command|argv, shell, cwd, env, timeout_ms, output_limit_bytes, execution_mode, idempotency_key)`：command与argv二选一；PowerShell、CMD明确解释器；WSL单独发行版和Linux cwd。返回真实退出码、输出、截断、后端和权限。不能使用 `codex exec` 或 `turn/start` 代理普通执行。

### 长任务

`session_start/read/write/kill/list`及可选`session_resize`，复用官方command/exec processId、流式输出和stdin。区分starting、running、exited、failed、lost、unknown；输出有游标、有界缓存、截断和缺口提示；默认不持久化终端原文。

保存归属、runtime_generation、创建时间、工作目录、退出状态和控制能力。仅前端断线而桥接及后端连接仍存活时可以续读；App Server或桥接重启后不得假称原进程可恢复。非幂等操作不自动重跑，终止只针对本桥拥有的会话。

### 文件

`read_file/list_dir/search_files/search_text/file_add/file_patch/file_move/file_delete`。读取优先官方fs接口；缺少语义时经官方command/exec复用现成OS/Git工具，标记真实后端。字节base64传输，UTF-8文本明确BOM、CRLF、行范围与大小上限。

file_add禁止覆盖：可采用官方fs/writeFile写入同目录唯一临时文件，再经官方执行层以不覆盖语义移动到目标；不能先检查存在再无条件覆盖。仅清理自己创建的临时文件。删除显式传入recursive与force，默认均false，不继承官方可能宽松的默认。跨卷移动不保证原子性。

Patch通过官方command/exec调用现成git apply，先check后apply，可校验基础SHA-256。返回native_codex_patch=false，不把它称为Codex原生Patch。不使用--reject或忽略冲突，不重置外部工作区。桥接内部锁不能锁住Desktop或编辑器的外部写入，必须如实说明并检测冲突。

### Git

`git_status/diff/log/branch/commit`，调用实际安装Git，不重写Git。argv和路径分隔，不拼接不可信Shell。diff禁用外部diff/textconv。commit显式文件及消息，不捎带其他已暂存文件，不改全局Git身份。首发不提供force push、amend或历史重写工具。

### Browser、Computer Use与Remote

目标接口为browser_start/snapshot/click/fill/press/scroll/navigate/close，以及computer_snapshot/click/type/press/scroll/wait。Browser 遵循上方用户批准的 Tabbit 专项变更；Computer Use 仍仅在官方宿主可授权直接调用路径实测通过后发布。未验证时明确不可用，不换用另一个视觉模型或 AgentDock 服务。

必要的桥接专用上下文thread可以创建，但必须验证不触发推理；禁止把用户Desktop thread、turn或授权标识伪装成自己的。不得因为需要真正的模型回合才能工作而偷偷启动模型。

截图必须包含时效和坐标空间，动作绑定新鲜观察/真实窗口；屏幕锁定、权限未授予、宿主通道缺失均返回具体原因。只在受控测试页面和本项目测试窗口验收，不操作业务页面。

Remote状态须区分本桥实例和Desktop实例；本桥disabled不能推断手机离线。enable、disable、pair不属于doctor自动行为。首发可只读，管理能力另验收。

## 6. 能力、更新与兼容

分别记录presence、callability、upstream_maturity、adapter_status、risk_level、enabled、reason和最后测试。稳定接口可能高风险，不能混为一谈。PASS、FAIL、NOT_TESTED、UNVERIFIED、DISABLED、UNAVAILABLE必须分开。

启动用轻量安装指纹；版本变化、缓存损坏、显式doctor刷新时再导出稳定及实验Schema。请求和可用响应均校验；Hash包含实际使用的请求及响应定义。保留前后差异，未知必填字段、已用方法删除、类型变化使受影响适配器拒绝执行，不开放任意RPC透传。

结构无破坏变化不等于行为已通过。兼容须有实际契约回归；模拟Schema升级不能冒充真实官方版本升级。自动适配只使用已审查的确定性映射，不调用LLM生成并立即执行适配器。

运行中有在途任务或会话时报告update_pending，不能杀任务或Desktop。无在途任务时重建自己拥有的连接。新接口默认未启用，单个实验接口失效不拖垮整个MCP。

## 7. 零模型证据

执行出口使用经过审查的确定性RPC白名单，拒绝turn/start、review/start、自动压缩、agent任务等。单独审查GUI插件和必要上下文，未知下游工具不自动加入白名单。

证据分三层：实际发出方法及计数；本桥拥有的App Server/插件调用链；受控测试模型端点及网络观测。计数必须由实际事件产生，不写死0。测试端点无请求只证明该端点；没有全进程抓包就标unknown，不宣称全机无模型流量。

外部用户显式执行的代码或Git hook可能自行调用模型，不等于桥接自主决策。核心验收使用无此行为的受控工程。

## 8. 并发、重试与恢复

写操作在桥接内部串行化，支持基础哈希和事后校验，不能声称全局文件锁。幂等键和参数摘要持久化；同key不同参数拒绝；结果丢失或进程重启时返回execution_state_unknown，不重复副作用操作。

响应等待超时不证明任务没执行。官方连接断开必须结束待响应请求并标明状态未知。后续新调用可重连，不重放旧写入。会话输出已缓存部分可读，后端进程无损恢复不可无条件保证。

## 9. 代理

继承HTTP_PROXY、HTTPS_PROXY、ALL_PROXY、NO_PROXY；按本项目配置读取WinINET或WinHTTP诊断，必要时将可解析显式HTTP代理映射到自己的子进程。不得改系统代理或把PAC/SOCKS伪装成HTTP。NO_PROXY保留loopback。

分别报告配置存在、子进程环境验证、目标Runtime实际路由验证。Shell联网不代替Remote/WebSocket路由证据。地址和秘密脱敏，不记录代理凭据。

## 10. 安装和日志

Windows 11优先，交付独立exe、源码和锁定依赖。CLI包括install/status/doctor/serve/version/capabilities，允许开发call和安全的本机凭据取用。默认不注册服务、不改全局PATH、不修改其他软件。

配置位于 `%USERPROFILE%/.codex-control-mcp/config.toml`；cache存Schema，state存会话/幂等摘要，logs存审计。HTTP凭据只通过环境或Windows DPAPI保护，不保存明文、不默认打印、不上传聊天。

日志回答调用工具、后端方法、版本、耗时、结果与代理证据层次；默认不保存完整命令、文件正文、stdout/stderr、密码、Token、Cookie或完整环境值。返回授权客户端的内容不等于允许长期落日志。

## 11. 性能与失败

热启动小负载桥接处理p95目标<100ms，分别报告冷启动、Schema导出、官方RPC等待和网络开销。目标不是已测成绩。错误以结构化code、message、retryable返回，工具错误必须isError，非零退出不得伪成功。

主要错误包括runtime_missing、version_incompatible、capability_unavailable、capability_unverified、authentication_required、concurrent_modification、session_lost、execution_state_unknown、invalid_arguments、output_limit_exceeded、idempotency_conflict、update_pending。

## 12. 验收与完成

保留原A—J：官方发现、版本重新发现、Shell标记、文件往返、Git、官方Browser页面读取、官方Computer Use截图/点击/输入、目标后台代理、更新兼容、零模型证据。增加stdio/HTTP鉴权、会话控制、故障恢复、重复请求和真实权限继承。全部测试使用独立项目，不复用业务内容。

1A只代表核心链路内测，不代表原第一阶段完成。1B须补齐GUI、ChatGPT网页、目标代理和完整模型证据；缺项保留BLOCKED/NOT_TESTED，不能删掉验收项。

“直到完美”执行为持续修复本轮可复现缺陷，对已实现范围完成回归，留下未满足的外部条件和准确续接断点；不宣称绝对无bug，不用伪PASS消除缺项。报告包含时间、操作系统、官方路径/版本、Schema、测试输入摘要、原始安全返回、断言和PASS/FAIL/BLOCKED/NOT_TESTED。

## 14. 本轮本机部署补充

本轮发现，直接分离启动的服务没有通过远程启动命令结束后的存活复查。采用单独命名的 Windows 按需任务 `Codex-Control-MCP-OnDemand` 托管本项目：当前交互用户、Highest、不存密码、无任何自动触发器、不设开机或登录自启动。此任务不是额外沙箱，也不负责模型推理。

创建前保存该任务是否存在；已有任务的执行文件、参数、权限或触发器与本项目不符时拒绝覆盖。仅管理本项目的任务，不更改其他计划任务、Windows 服务、AgentDock、Codex Desktop 或防火墙。最终交付须在不同远程调用之间复查同一服务，不能只以安装命令期间短暂在线作为验收。

官方 GUI 的应用访问仍需实际授权。应用授权表单可转发到支持相应交互的外部客户端；没有真实用户决定时保持取消状态。窗口枚举不替代截图、点击和输入验收；本轮这些验收项保持未完成。
