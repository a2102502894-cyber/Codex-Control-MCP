# 0.2.1：执行进度与桌面控制释放

## 长任务

`exec_command` 默认 `execution_mode=auto`：使用官方流式执行，只启动一次命令，等待约一秒后返回已有输出。如果 `completed=false`，调用方必须使用返回的 `session_id` 和 `next_cursor` 继续 `session_read`，向用户报告进展，直到收到最终退出码。`ok=true` 只代表此次工具调用成功，不能把仍在运行的命令报告为完成。

`yield_time_ms`（0–10000）控制此次等待；`timeout_ms` 仍控制进程期限。需要旧的同步语义时明确指定 `execution_mode=buffered`。内部文件、Git、远程文件操作继续使用完整结果语义。读取输出须检查 `has_more`、`cursor_gap`、`output_truncated`；不要因为没看到输出就重发命令。

工具描述增加中文运行状态和输出 schema。HTTP 使用 MCP SSE 响应；客户端提供 `progressToken` 时，服务每五秒发出等待状态通知。这不是虚构的完成百分比。没有 token 的客户端仍可通过 auto 模式拿到会话回执。客户端是否把通知显示在界面上由宿主决定；不能保证修复 ChatGPT Android 的所有空白或同步问题。

原始诊断：0.2.0 的同步命令会把“立即输出开始、三秒后输出结束”一起延迟到约 3.087 秒后返回，日志中另有约 111.84 秒的同步等待。截图对应时段没有新工具调用记录，不能据此断言所有空白都由 MCP 引起。

## Computer Use

桌面工作流结束时调用 `computer_close`。它释放本桥拥有的官方连接和子进程，不关闭用户应用。连续动作之间保留连接和快照；最后一次动作后空闲 120 秒自动释放，失败动作也安排清理。旧定时器不能关闭新连接，关闭和动作串行处理。

关闭后快照失效，下一次须从 `computer_snapshot` 开始。关闭会等待官方 MCP stdio 的退出清理；未退出时明确报错并保留连接引用，不把“发出了关闭请求”冒充“已经退出”，也不立即建立第二条连接。

## 部署与回滚

部署前备份源码及服务恢复配置、核对活动命令和桌面连接。验证候选服务后重启本桥。增加 `computer_close` 会使启用相同功能的工具数增加一；恢复控制器的预期版本、工具数须相应更新。控制器支持每个候选单独设置 `expected_version` 与 `expected_tool_count`，因此旧 LKG 回滚候选可以保留旧版本和旧数量。

新增工具是否出现在现有对话取决于宿主刷新工具列表。旧对话即使没有 `computer_close`，仍有空闲释放兜底；新对话应获取新工具描述。无需重新配对 OAuth。
