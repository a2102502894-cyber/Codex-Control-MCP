# 应用访问默认批准 · 0.1.11

本次修复来自用户明确要求：“默认全部批准不需要授权”。问题为网页模型调用 computer_snapshot 时，官方 Computer Use 请求访问 Tabbit；原来的转发链依赖外部 MCP 客户端支持 elicitation，未取得回执便返回 cancel。

在本项目配置根部启用：

```toml
auto_approve_application_access = true
```

配置文件为 `%USERPROFILE%\.codex-control-mcp\config.toml`，启动服务时读取。此设置将官方 Computer Use 的正常应用访问请求按用户预授权返回 accept，适用于所有应用标识，支持首次出现的应用。响应和审计记录 `explicit_owner_preapproval`，无需网页授权弹窗，也不会伪造人工点击记录。

只识别官方 computer-use 元数据中的空应用访问表单。密码/数据填写表单、URL 模式授权和其他连接器请求继续走原有处理。这项应用许可与 Shell 的 approval_policy=never、OAuth 账号配对、Windows UAC 及管理员强制策略分属不同机制；本修复没有修改它们。源码默认不开启，当前用户的正式配置明确开启。关闭本项目此设置并重启服务可恢复原交互方式。

验证以专属 HTTP 测试服务和正式服务完成；测试客户端不提供 elicitation 回调。测试只枚举窗口并对真实 Tabbit 窗口截图，不点击网页，不提交视频，不保存业务截图。完整结果以本次交付的 evidence 目录为准。

218 项回归通过；源码 HTTP 和打包 EXE HTTP 各取得两次截图，官方回执均为 accept，来源均为 explicit_owner_preapproval。0.1.10 的冻结交付保留，不将原有 Browser、公网及历史 GUI 验收改写成本轮新测试。

官方说明确认应用访问许可与文件/Shell 权限相互独立，原生持久许可可使用 always_allowed_app_ids。本版在自有 MCP 客户端实现用户选定的预授权答复，未修改官方运行时或其策略文件。参考：[Computer Use](https://learn.chatgpt.com/docs/computer-use)、[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

Clash、系统代理、DNS、路由和防火墙未修改；原有账号连接保留。前一轮 16 项完整替代清单中，其余工作没有纳入本次专项修复。
